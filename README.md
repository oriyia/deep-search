# deep-search

Скилл для ИИ-агентов (Claude Code и совместимых) — **универсальный глубокий поиск с ветвлением**:
бриф поиска → дерево веток (субагенты или последовательно) → проверка и сведение → хранилище
найденного, которое читают и человек, и агент.

Статус: скилл собирается по [плану](docs/plans/2026-10-05-deep-search-plan.md) из
[спецификации](docs/specs/2026-10-05-deep-search-design.md). Язык скилла и шаблонов — русский.

---

## Что это

Агент, которого просто просят «найди», делает пару запросов и останавливается, верит сниппету
вместо страницы, принимает перепечатки за независимые подтверждения и каждый раз начинает с нуля.
deep-search задаёт порядок работы в три части:

1. **Подготовка** — бриф: что ищем, зачем, в каких границах и что считается ответом.
2. **Поиск** — дерево веток по типу вопроса, оценка источников по шкале A–F × 1–6, журнал,
   остановка по правилам, поатомная проверка ключевых утверждений, сведение одним автором.
3. **Сохранение** — хранилище в два слоя (свидетельства и выводы), которое переиспользуют
   следующие поиски, без свалки и без роста контекста.

Подробно, от общего к частному, — [docs/guide.md](docs/guide.md). Сравнение с другими
инструментами, что откуда взято и что своё, — [docs/comparison.md](docs/comparison.md).

## История решений

Почему скилл устроен так, как устроен. Новое решение пишется сверху; отменённое не правится —
новая запись называет, что сменилось.

### 2026-10-05 · требования к разработке — в `CONTRIBUTING.md`

В спецификации, раздел 2.1, правила разработки скилла лежали в отдельном файле для одного
инструмента. Теперь они в `CONTRIBUTING.md`, сформулированы для каждого, кто вносит изменения, а
служебные файлы инструментов разработки в репозиторий не входят. Раздел 2.1 спецификации и
[docs/guide.md](docs/guide.md), раздел 8, поправлены.

Почему. Репозиторий может стать публичным: правило, от которого зависит целость проекта, должно
приезжать с `git clone` к любому участнику, а личные настройки инструментов — оставаться в рабочей
копии.
Пересмотреть, если: у проекта появятся участники, которым нужны общие настройки инструмента
разработки.

### 2026-10-05 · спецификация v1

Скилл проектируется по [спецификации](docs/specs/2026-10-05-deep-search-design.md): ядро-маршрутизатор
с подфайлами по этапам, пресеты, шаблоны и скрипт проверок с тестами; бриф с обязательностью полей
по уровню и типу вопроса; дерево веток от типа вопроса и бюджеты S–XL; шкала A–F × 1–6; проверка
ключевых утверждений отдельным субагентом; хранилище в два слоя. Принятые решения и их источники —
спецификация, раздел 1.3.

Почему. Решения опираются на [исследование](research/2026-10-05-search-landscape/README.md) от
2026-10-05: инструменты и продукты, исследования агентного поиска, оценка источников, хранение и
переиспользование, контекст, ветвление и бюджет, систематические методы.
Пересмотреть, если: обкатка (тикет 11) или оценка «со скиллом / без» (тикет 12) покажут, что
бриф, ветвление или проверка не окупают своей цены.
