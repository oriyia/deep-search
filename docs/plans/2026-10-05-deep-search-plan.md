# deep-search — план реализации

> **Исполнителям-агентам:** работать по тикетам. Реализацию и шаги TDD внутри тикета выбираете сами по
> спецификации и коду. Отметки — чекбоксы `- [ ]`; выполненный критерий отмечается `- [x]`.

**Цель:** универсальный скилл глубокого поиска с ветвлением — бриф, дерево веток, проверка и
сведение, хранилище найденного — с проверками формы и хранилища в коде.

**Архитектура:** ядро-маршрутизатор `SKILL.md`, подфайлы `references/` по этапам, пресет
`presets/technology.md`, шаблоны `templates/`, один скрипт `deep_search.py` (`doctor`, `init`, `lint`,
`index`, `cost`, `self`) с тестами. Ветки — субагентами или последовательно, с одним контрактом.

**Стек:** Markdown + YAML frontmatter; JSONL для журналов; Python 3.10+ stdlib; `unittest`.

**Спецификация:** `docs/specs/2026-10-05-deep-search-design.md` — план опирается на неё, исполнитель
читает нужные разделы спецификации (по оглавлению) вместе с тикетом.

## Глобальные ограничения

- Тексты скилла — по-русски; имена файлов, полей брифа, slug — английские.
- `description` ≤500 символов; `SKILL.md` ≤85 строк и ≤5 500 символов; «Всегда» и «Этапы» — в первых
  60 строках; заголовки ядра: «Всегда», «Этапы», «Эпизодически», «Где что лежит».
- Подфайл ≤200 строк и ≤12 000 символов; `verify-merge.md`, `store.md` — ≤8 000; первая строка —
  «Когда читать: …»; оглавление, если больше 100 строк.
- Пресет ≤12 000 символов; `templates/brief.md` ≤4 000; задание ветки ≤2 000, ответ ветки ≤5 000.
- INDEX ≤100 строк; карточка ≤300 строк; утверждений темы ≤200.
- Вывод `deep_search.py` ≤9 000 символов, главное — в первых 2 000, хвост «… ещё N».
- `deep_search.py` — один файл, Python stdlib ≥3.10, без внешних зависимостей.
- `python3 -m unittest discover tests` — зелёный после каждого тикета.
- В репозитории нет непубличных сведений — внутренних документов и организаций, где работает
  пользователь, — и описаний рабочего окружения: репозиторий может стать публичным.
- Факт живёт в одном месте: подфайлы не повторяют друг друга, ссылаются; в ядре нет обоснований.
- Документация для человека — `docs/guide.md` (устройство и использование) и `docs/comparison.md`
  (сравнение, заимствования) — правится в том же тикете, что и поведение, которое она описывает.
  Волна 3–7 эти файлы не правит: расхождения — в отчёт тикета, ведущий вносит их после волны.
- Решение, расходящееся со спецификацией, — сначала пользователю; принятое — README, «История
  решений» (новое сверху, «Пересмотреть, если»).
- Коммит — только по команде пользователя; сообщение по-русски, повелительное наклонение, с
  заглавной, без точки, без префиксов и подписей.

**Оглавление подфайла** длиннее 100 строк — строка «Содержание: …» в первых 20 строках; после неё
названы все разделы `## ` (ссылками или текстом). Так его проверяет `self` (`ref-toc`).

**«Когда читать» в шаблонах** — комментарием по синтаксису файла, чтобы скопированный шаблон
оставался чистым для `lint`: в YAML — `#` первой строкой; в Markdown с frontmatter — `#` второй строкой
внутри frontmatter; в Markdown без frontmatter — `<!-- … -->`.

**Поля брифа** — плоские скаляры верхнего уровня frontmatter, без вложенных ключей и `[]`: пустое
значение — незаполненное поле (так их читает `lint`).

**Заголовки подфайлов** — якоря для ссылок между файлами («`<файл>`, раздел «<заголовок>»»);
исполнитель может добавить свои, но эти — дословно:

- `brief.md`: «Порядок», «Поля», «Условная обязательность», «Уровень и контрольная точка 0»,
  «Вопросы интервью», «Поправки».
- `branching.md`: «Форма дерева», «Правила дерева», «Бюджет», «Остановка», «Контракт ветки»,
  «Поручение субагенту», «Контрольные точки», «Без субагентов», «Контекст ведущего», «plan.md
  прогона».
- `sources.md`: «Проходы», «Обязательные приёмы», «Запросы», «Инструменты», «Шкала», «Независимость»,
  «Свежесть», «Красные флаги», «Журнал и улики».
- `verify-merge.md`: «Проверка», «Поручение проверяющему», «Сведение», «Отчёт», «Самопроверка».
- `store.md`: «Где», «Раскладка», «Прогон», «Форматы», «Переиспользование», «Запись», «Против свалки».
- `environment.md`: «Текст страницы», «PDF», «JS-страницы», «Архив и мёртвые ссылки», «API по
  областям», «Claude Code», «Другие агенты».
- `presets/technology.md`: «Типы вопроса», «Первоисточники», «Источники охвата», «Шаблоны запросов»,
  «Расширение по связям», «Приёмы», «Отсев», «Данные для оценки», «Признаки за и против», «Подсказки
  для exclusion_criteria», «Свежесть», «Разделы отчёта».

**Перечисления** (значения дословно):

- `question_type`: `fact` · `validation` · `comparison` · `options` · `exhaustive_list` ·
  `replacement` · `compliance`; `mode`: `one_off` · `update`; `stakes`: `low` · `normal` · `high`;
  `coverage_goal`: `first_sufficient` · `representative` · `exhaustive`; `budget_tier`: `S` · `M` ·
  `L` · `XL`; `store`: `library` · `project` · `none`; `preset`: `technology` · `none`.
- `status` в ответе ветки: `done` · `partial` · `not_found` · `budget_exhausted` · `blocked`; в
  `plan.md` — они же и `pending` · `running` · `closed`.
- Статус утверждения: `live` · `stale` · `superseded→C-…` · `retracted`; карточки: `live` · `stale` ·
  `archived`; виды записей `log.md`: `search` · `update` · `verify` · `archive`; `method` журнала:
  `query` · `browse` · `citation` · `api`; класс свежести: `V0` · `V1` · `V2` · `V3`.
- Код оценки — `^[A-F][1-6]!?$`.

**Уровень по умолчанию от типа вопроса** (стартовое, калибруется в тикете 11): `fact` → S;
`validation`, `comparison`, `replacement`, `compliance` → M; `options`, `exhaustive_list` → L;
`exhaustive_list` при `coverage_goal: exhaustive` и больше 50 ожидаемых объектов → XL.

**Идентификаторы:**

- slug — `^[a-z0-9]+(-[a-z0-9]+)*$`; прогон — `<ГГГГ-ММ-ДД>-<slug>`, при совпадении суффикс `-2`.
- `task_id` — `^B\d+(\.\d+)*$`; улика — `ev<N>` внутри ветки, ссылка из другой ветки или из сведения —
  `<task_id>:ev<N>`.
- Находка — `F<N>` по порядку внутри прогона, до сохранения: строка реестра находок в разделе 4
  `report.md` и id в `verify.md`; при сохранении получает id утверждения.
- Утверждение — `C-<slug>-<NNN>` (три цифры, по порядку в теме); источник — `S-` + первые 8 hex
  sha256 ключа; ключ — DOI в нижнем регистре → канонический URL без фрагмента и `utm_*` → sha256
  текста.

**Форматы хранилища** — таблицы Markdown, строка начинается с `| <id>`, символ `|` внутри текста
экранируется `\|`:

- `claims/<slug>.md`: `| id | код | утверждение | предмет | источники | цитата | проверено | свежесть |
  статус |`; источники — `S-…[ §место]` через `; `; свежесть — `V2→ГГГГ-ММ-ДД`, у V0 — просто `V0`.
- `sources.md`: `| id | тип | заголовок | владелец | опубликовано | обращение | URL | архив | надёжен
  для |`.
- `INDEX.md`: `| slug | TL;DR | keywords | статус | проверено | годен до |`; `keywords` — `aliases` и
  `keywords` карточки через `, `.
- `log.md`: заголовок `## [ГГГГ-ММ-ДД] <вид> | <slug> | <прогон>` и до двух строк текста; без прогона —
  `—`.
- Карточка — frontmatter `topic`, `title`, `tldr`, `aliases`, `keywords`, `status`, `checked`,
  `expires`, `runs`; списки — строки через `, `; все утверждения V0 — `expires: —`.

**Форматы прогона:**

- Журнал `branches/<task_id>.jsonl` — объект на строку с ключами `ts`, `branch`, `method`, `source`,
  `query`, `filters`, `shown`, `screened`, `kept`, `dupes`, `note`, `capture` (последний — только у
  ключевых страниц).
- Улика в `branches/<task_id>.md` — `ev<N> | <дата> | <буква> | <URL> §<место> | orig: <происхождение>
  | → <ключ утверждения> | «<цитата ≤25 слов>»`; дата — дата проверки, дата публикации — в `orig` после
  происхождения, нет её — «б/д».
- Ответ ветки — по `templates/branch-return.yaml`; вложенные поля: `findings[]` — `key`, `claim`,
  `evidence`, `code`, `fresh`; `log_summary` — `queries`, `sources_viewed`, `new_items_last_round`,
  `known_items_hit`.
- `verify.md` — заголовок `## <ГГГГ-ММ-ДД>` и таблица `| id | вердикт | улика | URL §место | цитата |
  расхождение |`; вердикт — `да` · `частично` · `нет`; у «нет» расхождение начинается с «не говорит»,
  «противоречит» или «не открыта».
- `plan.md` — до 4 000 символов: шапка (уровень, бюджет, потрачено, WebSearch, раунд, точки), таблица
  `| id | цель | статус | бюджет план/факт | выход |`, разделы «Решения» и «Следующий шаг».
- `report.md` — без frontmatter, по `templates/report.md`.
- `manifest.json` — ключи `id`, `tier`, `preset`, `env` (вывод `doctor --json`), `budget`
  (`planned`, `used`), `stop_reason`, `counts` (`found`, `dupes`, `screened`, `kept`), `branches`
  (список `{id, status}`).

**Контракт `deep_search.py`:**

- Коды выхода: 0 — нарушений нет (предупреждения допустимы), 1 — есть нарушения, 2 — ошибка вызова или
  не реализовано.
- Строка нарушения — `<путь>: <правило>: <подробность>`; предупреждение — та же строка с префиксом
  `warn: `. Правила — kebab-case, имя правила — то, что проверяют тесты.
- Ошибки: форма скилла, обязательные поля, перечисления, ссылочная целостность, размер ответа ветки.
  Предупреждения: бюджеты хранилища (INDEX, карточка, утверждения темы), просроченные утверждения.
- Бюджеты и оценка токенов — константы в начале файла с комментарием «почему» и ссылкой на раздел
  спецификации; оценка токенов — кириллица / 2,7 + прочее / 4,0, дата константы 2026-10-05.

**Ключевые тест-кейсы:**

- скилл в нужной форме → `self` код 0; ядро в 86 строк → `core-lines`;
- хранилище и прогон из шаблонов → `lint` код 0;
- бриф уровня S без `done_criteria` → `brief-required`;
- ответ ветки в 5 001 символ → `return-chars`;
- утверждение со ссылкой на несуществующий `S-…` → `claim-source`;
- карточка без строки в INDEX → `index-coverage`;
- два источника с одним ключом → `source-dup`;
- просроченное утверждение → `warn: … claim-expired`, код 0.
