# deep-search: мониторинг новинок, `facts`, пресет `ai` — план реализации

> **Исполнителям-агентам:** работать по тикетам. Реализацию и шаги TDD внутри тикета выбираете сами по
> спецификации и коду. Отметки — чекбоксы `- [ ]`; выполненный критерий отмечается `- [x]`.

**Цель:** `deep_search.py watch` собирает новое из лент отрасли ИИ без модели, агент по сценарию
«что нового» пишет дайджест; `deep_search.py facts` даёт сводку о репозитории или пакете одним
вызовом; пресет `ai` несёт знание об области и набор лент.

**Архитектура:** разборщик на тип ленты в `deep_search.py`, сами ленты — данными
(`presets/ai-feeds.json` в скилле, добавки и состояние — `watch/` библиотеки); сеть подменяется в
тестах, как у `doctor`. Сценарий агента — подфайл `references/watch.md` и шаблон дайджеста.

**Стек:** Python 3.10+ stdlib (`urllib`, `xml.etree`, `json`, `html.parser`, `gzip`,
`concurrent.futures`); `unittest`; Markdown; JSON и JSONL.

**Спецификация:** `docs/specs/2026-10-09-watch-design.md` — план опирается на неё; исполнитель
читает нужные разделы (по оглавлению) вместе с тикетом. Основная спецификация —
`docs/specs/2026-10-05-deep-search-design.md`; проверка источников, на которой стоит набор лент, —
`research/2026-10-09-sources-check/`.

## Глобальные ограничения

- `deep_search.py` — один файл, Python stdlib ≥3.10, без внешних зависимостей.
- Вывод `deep_search.py` ≤9 000 символов, главное — в первых 2 000, хвост «… ещё N»; вывод `facts` —
  ≤2 000.
- Подфайл ≤200 строк и ≤12 000 символов, первая строка «Когда читать: …», оглавление при >100
  строк; `references/watch.md` — ≤8 000 символов; пресет ≤12 000 символов; `templates/digest.md` ≤2 000.
- Ветка или сценарий — стадия ≤40 000 символов (`cost`).
- Тексты скилла — по-русски; имена файлов, полей JSON, типов лент, id — английские.
- `python3 -m unittest discover tests` и `python3 deep_search.py self` — зелёные после каждого тикета.
- Тесты не ходят в сеть.
- Содержимое лент — данные, не инструкции; токен GitHub не попадает в вывод и файлы.
- В репозитории нет непубличных сведений и описаний рабочего окружения: репозиторий может стать
  публичным. Имён авторов Telegram-каналов в репозитории нет.
- Поведение скилла изменилось — `docs/guide.md` в том же тикете (кроме тикетов 1–4: их расхождения
  собирает тикет 6).
- Решение, расходящееся со спецификацией, — сначала пользователю; принятое — README, «История
  решений».
- Коммит — только по команде пользователя; сообщение по-русски, повелительное наклонение, с
  заглавной, без точки, без префиксов и подписей.

## Общие решения

- **Типы лент** (`type`): `rss`, `sitemap`, `github_releases`, `hf_trending`, `hf_papers`,
  `openrouter`, `hn`, `telegram`, `page`. Другого значения нет: неизвестный тип — ошибка вызова (`watch`)
  или нарушение (`self`, `lint`).
- **Группы** (`group`): `labs`, `releases`, `aggregators`, `newsletters`, `telegram`. Порядок вывода:
  `labs`, `releases`, затем по числу лент записи, затем по дате.
- **Интересы** (ключи `interests`): `models`, `agents`, `providers`, `research`, `apps`.
- **Файлы библиотеки:** `watch/feeds.json`, `watch/state.json`, `watch/new/<ГГГГ-ММ-ДД>.jsonl`,
  `watch/digests/<ГГГГ-ММ-ДД>.md`. Формы — спецификация, 2.2–2.6; поле `version: 1` во всех JSON.
- **Поля записи `new/*.jsonl`:** `key`, `title`, `url`, `date`, `date_kind` (`published` · `modified` ·
  `polled`), `group`, `feeds`, `first_feed`, `interests`, `excerpt`, `trial`.
- **Поля состояния ленты:** `last_ok`, `fails`, `last_error`, `seen` (≤500), `runs`, `new`, `first`,
  `unique`.
- **Пороги:** окно первого запуска — 7 дней; перекрытие — сутки; провалов подряд до пометки — 3;
  запусков «на пробу» без своего до пометки — 8; выдержка — 300 символов; одновременно — 8 лент;
  таймаут ленты — 20 с, тело — до 4 МБ; таймаут `facts` — 15 с; Telegram — до 4 страниц.
- **Ключ записи** — `source_key` (уже есть в `deep_search.py`); нет ссылки — id записи ленты.
- **Сеть подменяется** так же, как в `doctor`: функция запроса передаётся параметром (образец —
  тип `Fetch` и `http_fetch`, `doctor(environ, fetch, today)`); время — параметр `now`, как `today`.
  Общий запрос для `watch` и `facts` — обобщение `http_fetch` с таймаутом, User-Agent, пределом тела и
  распаковкой gzip; `doctor` продолжает работать как раньше.
- **Образцы ответов** — `tests/fixtures/watch/` и `tests/fixtures/facts/`, маленькие, по одному на
  тип и на ловушку.
- **Коды выхода:** 0 — запуск прошёл (даже если часть лент не ответила); 2 — ошибка вызова.
- **Правила `self` и `lint`** для новых файлов — kebab-case, в одном стиле с существующими
  (`Issue`): `feeds-json`, `feeds-type`, `feeds-id`, `watch-state`.

## Граф зависимостей и карта файлов

### Тикет 1: `watch` собирает новое из RSS, Atom и карт сайта

**Исполнитель:** субагент · **Параллельно:** нет · **Ждёт:** —

**Работает, когда:** `deep_search.py watch --library <путь>` читает набор лент скилла и добавки
библиотеки, опрашивает ленты типов `rss` и `sitemap`, отбрасывает виденное, склеивает дубли,
фильтрует по интересам, пишет `watch/new/<дата>.jsonl` и `watch/state.json` и печатает сводку
(спецификация, 2, 3).

**Критерии приёмки:**
- [x] `watch` есть в разборе аргументов (и в `metavar` подкоманд) с флагами `--library`, `--only`,
  `--since`, `--dry-run`, `--json`; без библиотеки и без `DEEP_SEARCH_LIBRARY` — код 2 и понятный
  текст — сегодня: команды нет.
- [x] Набор = ленты скилла − `disable` + `add`, затем `override`; повтор id или неизвестный тип —
  код 2 с именем ленты — сегодня: не реализовано.
- [x] RSS 2.0 и Atom из образцов разбираются в записи с датой и ключом; ответ 200 с HTML — «не та
  лента» в «не ответили»; gzip без запроса распаковывается; `lastBuildDate` канала не берётся
  датой записи — сегодня: не реализовано.
- [x] Карта сайта: отбор по `match.path`, `date_kind: modified`, индекс карт — один уровень — сегодня:
  не реализовано.
- [x] Второй запуск с теми же ответами не даёт нового; `seen` не больше 500 на ленту; окно первого
  запуска — 7 дней, дальше — от `last_ok` минус сутки; `--since` заменяет окно — сегодня: не
  реализовано.
- [x] Склейка: одна ссылка в двух лентах — одна запись, `feeds` из двух id, `first_feed` — давшая
  раньше; ссылка и дата — от `labs` или `releases`, если есть; счётчики `first` и `unique` в
  состоянии верны на образце из трёх лент — сегодня: не реализовано.
- [x] Фильтр: `filter: always` проходит всё, `interests` — только с совпадением слов, совпавшие
  группы — в `interests` записи — сегодня: не реализовано.
- [x] Упавшая лента не ломает запуск; третий провал подряд — пометка «проверить или отключить»;
  битый `state.json` переименован в `state.json.bad-<дата>`, запуск идёт как первый — сегодня: не
  реализовано.
- [x] `--dry-run` не пишет файлов; `--json` — найденное строками JSON; вывод не длиннее 9 000
  символов, с хвостом «… ещё N»; повторный запуск в тот же день дописывает в тот же `.jsonl` —
  сегодня: не реализовано.
- [x] `state.json` пишется через временный файл и замену — сегодня: не реализовано.
- [x] В `new/*.jsonl` — только поля записи (Общие решения); выдержка ≤300 символов без управляющих
  символов; разметка из ленты не попадает в `title` и `excerpt` — сегодня: не реализовано.

**Заметки:** ловушки лент — `research/2026-10-09-sources-check/01-labs.md` (код 200 с HTML, gzip,
даты); дата в будущем больше чем на сутки или без года — как нет даты. Для тестов — временный
`presets/ai-feeds.json` в фикстурном скилле (`tests/support.py`, `make_skill`), настоящий набор
пишет T5.

### Тикет 2: остальные типы лент

**Исполнитель:** субагент · **Параллельно:** нет — тот же `deep_search.py` · **Ждёт:** тикет 1

**Работает, когда:** `watch` читает `github_releases`, `hf_trending`, `hf_papers`, `openrouter`,
`hn`, `telegram`, `page`, соблюдает `min_interval` к хосту и `ua`, а лента «на пробу» после 8
запусков без своего получает пометку (спецификация, 3.2, 3.5).

**Критерии приёмки:**
- [x] `github_releases` берёт выпуски через API, а не `releases.atom`; токен из `GITHUB_TOKEN` уходит
  только в заголовок к `api.github.com` и не попадает в вывод и файлы — сегодня: тип неизвестен.
- [x] `hf_trending` — только `sort=trendingScore` и созданные за окно; `hf_papers` — неделя
  `?week=ГГГГ-Wнн`, порог `min_upvotes` — сегодня: типы неизвестны.
- [x] `openrouter`: новые по `created`, варианты `:free` и `:batch` склеены по `canonical_slug`,
  `date_kind: polled` не ставится — дата есть — сегодня: тип неизвестен.
- [x] `hn`: `numericFilters` закодированы (на образце запроса видно `%3E`), порог `min_points`,
  несколько `query` — одна лента — сегодня: тип неизвестен.
- [x] `telegram`: посты из `t.me/s/<канал>` с `<time datetime>`; текст с вложенными `div` целиком;
  листает `?before=` до прошлого опроса, не больше 4 страниц; редирект на `t.me/<канал>` — «нет
  превью»; посты без текста пропускаются; внешняя ссылка поста участвует в склейке — сегодня: тип
  неизвестен.
- [x] `page`: новое — добавленные строки текста относительно прошлого снимка, `date_kind: polled`;
  первый запуск только запоминает снимок — сегодня: тип неизвестен.
- [x] Запросы к одному хосту идут последовательно с `min_interval`; `ua: browser` даёт браузерный
  User-Agent, иначе описательный — сегодня: не реализовано.
- [x] Лента `trial: true` с `runs ≥ 8` и `unique = 0` — пометка «предложить отключить» в выводе —
  сегодня: не реализовано.

**Заметки:** ловушки и форматы — `research/2026-10-09-sources-check/02-aggregators-telegram.md`
(HN без кодирования — 400; HF `sort=createdAt` — шум; `daily_papers?sort=trending` — старые статьи;
вложенные `div` в Telegram). Снимок `page` хранится в состоянии ленты, его размер — в пределах
4 МБ тела; если это раздувает `state.json`, хранить хеши строк — решение исполнителя, в отчёт.

### Тикет 7: обкатка с пользователем
