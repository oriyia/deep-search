## 1. Назначение и границы

### 1.1. Что делает

- **`watch`** — раз в несколько дней, по команде человека, собирает новое из лент по всей отрасли ИИ:
  первоисточники лабораторий и агрегаторы. Механика — скачать, разобрать, отбросить виденное,
  склеить дубли, грубо отфильтровать — в коде, без модели.
- **Сценарий «что нового»** — агент читает найденное `watch`, отбирает важное по интересам
  пользователя, проверяет по первоисточнику и пишет дайджест; по крупной новинке предлагает полный
  поиск, который становится темой хранилища.
- **`facts`** — сводка о репозитории или пакете одним вызовом: лицензия, выпуски, поддержка,
  уязвимости, использование, сопровождение — с источником у каждого значения.
- **Пресет `ai`** — знание об области ИИ для обычных поисков: модели, инструменты для агентов,
  поставщики, программы для ИИ.

### 1.2. Чего не делает

- Не запускается сам по расписанию: запуск — человек (терминал) или агент по просьбе.
- Не читает закрытые площадки (X, Discord, LinkedIn): только то, что отдаётся без входа и ключа.
- Не следит за LMArena и Epoch AI как за лентами: это данные для сравнения моделей (пресет), а не
  новости.
- `facts` не оценивает, не сравнивает и не ищет альтернатив.

### 1.3. Принятые решения

| # | Решение | Почему | Откуда |
|---|---|---|---|
| 1 | Мониторинг входит в работу, хотя основная спецификация (11) относила его ко второй версии; запуск вручную раз в несколько дней | Нужно быть в курсе отрасли; расписание не нужно — человек запускает сам | решение пользователя |
| 2 | Готовый набор лент — в скилле (`presets/ai-feeds.json`); добавки, отключения, «виденное», найденное и дайджесты — в библиотеке (`watch/`) | Улучшения набора приходят со скиллом; история одна на все проекты | решение пользователя |
| 3 | Типы лент — в коде (разборщик на тип), сами ленты — данными | Новая лента — строка, а не код; ловушки обходятся один раз в разборщике | решение пользователя; [01, 02] |
| 4 | Результат — дайджест в `watch/digests/`; полный поиск — по просьбе, как тема хранилища | Дёшево по умолчанию, глубоко по запросу | решение пользователя |
| 5 | Интересы: новые модели, инструменты для агентов, изменения у поставщиков, исследования, программы для ИИ | Задают фильтр в коде и отбор агента | решение пользователя |
| 6 | Telegram и другие внешние каналы — только авторские, прошедшие боковое чтение, «на пробу»; лента держится, пока даёт своё | Новостные пересказывают ленты, которые `watch` читает сам; ценны только те, что первыми пересказывают недоступное | решение пользователя |
| 7 | Сеть в тестах не трогается: подмена запроса и образцы ответов | Как в `doctor`; тесты быстрые и стабильные | основная спецификация, 8.2 |

## 2. Данные

### 2.1. Где

```
<скилл>/presets/ai-feeds.json          готовый набор лент и интересов
<библиотека>/watch/feeds.json          добавки, отключения, свои интересы
<библиотека>/watch/state.json          состояние лент
<библиотека>/watch/new/<ГГГГ-ММ-ДД>.jsonl   найденное запуском
<библиотека>/watch/digests/<ГГГГ-ММ-ДД>.md  дайджест агента
```

Библиотека — `DEEP_SEARCH_LIBRARY` или `--library`. `init` создаёт `watch/` с `feeds.json`-заготовкой
(пустые добавки и отключения). `state.json` и `new/` пишет только `watch`; коммитит человек.

### 2.2. Набор лент: `presets/ai-feeds.json`

```json
{
  "version": 1,
  "checked": "2026-10-09",
  "interests": {
    "models": ["model", "release", "weights", "модель", "веса"],
    "agents": ["agent", "MCP", "Claude Code", "Codex", "skill", "агент"],
    "providers": ["pricing", "rate limit", "deprecat", "API", "цена", "лимит"],
    "research": ["paper", "arXiv", "benchmark", "статья"],
    "apps": ["NotebookLM", "editor", "app", "launch", "приложение"]
  },
  "feeds": [
    {"id": "anthropic-site", "type": "sitemap", "url": "https://www.anthropic.com/sitemap.xml",
     "group": "labs", "lang": "en", "match": {"path": ["/news/", "/research/", "/engineering/"]},
     "filter": "always", "note": "lastmod — дата правки, а не публикации"}
  ]
}
```

Поля ленты:

| Поле | Обязательно | Что |
|---|---|---|
| `id` | да | уникальный slug |
| `type` | да | тип из 3.2 |
| `url` или `params` | да | адрес; у JSON-типов — параметры запроса (`query`, `min_points`, `repo`, `channel`) |
| `group` | да | `labs` · `aggregators` · `newsletters` · `telegram` · `releases` |
| `lang` | да | `en` · `ru` |
| `filter` | да | `always` — проходит всё; `interests` — только с совпадением слов интересов |
| `match` | нет | сузить внутри ленты: префиксы пути, префикс заголовка (`[AINews]`), исключения |
| `ua` | нет | `browser` — где описательный User-Agent режут; по умолчанию — описательный |
| `min_interval` | нет | секунд между запросами к хосту (arXiv 3, Reddit 60) |
| `trial` | нет | `true` — «на пробу»: в выводе помечается, статистика своего — к решению об отключении |
| `note` | нет | ловушка ленты одной строкой |

Слова интересов — подстроки без учёта регистра; в библиотеке их можно заменить по группе.

### 2.3. Добавки: `watch/feeds.json`

```json
{"version": 1, "add": [], "disable": ["<id>"], "override": {"<id>": {"filter": "interests"}},
 "interests": {}}
```

Набор = ленты скилла − `disable` + `add`, затем `override` по id. `interests` библиотеки заменяют
группу интересов целиком. Неизвестный тип или повтор id — ошибка вызова с понятным текстом.

### 2.4. Состояние: `watch/state.json`

```json
{"version": 1, "feeds": {"<id>": {
  "last_ok": "2026-10-09T12:00:00+00:00", "fails": 0, "last_error": "",
  "seen": ["<ключ>", "…"], "runs": 7, "new": 41, "first": 9, "unique": 3}}}
```

- `seen` — ключи записей, не больше 500 на ленту, старые вытесняются.
- `new` — сколько нового дала лента за все запуски; `first` — сколько раз она дала новость раньше
  всех; `unique` — сколько раз новость была только у неё.
- Пишется атомарно: временный файл и замена.

### 2.5. Найденное: `watch/new/<дата>.jsonl`

Строка на новость после склейки дублей:

```json
{"key": "anthropic.com/news/claude-haiku-5-5", "title": "…", "url": "https://…", "date": "2026-10-07",
 "date_kind": "published", "group": "labs", "feeds": ["anthropic-site", "hn", "seeallochnaya"],
 "first_feed": "anthropic-site", "interests": ["models"], "excerpt": "до 300 символов", "trial": false}
```

`date_kind`: `published` · `modified` (дата правки, как `lastmod`) · `polled` (даты нет — время
опроса). Повторный запуск в тот же день дописывает в тот же файл.

### 2.6. Дайджест: `watch/digests/<дата>.md`

По шаблону `templates/digest.md`: разделы по интересам; пункт — заголовок, 1–2 строки «что это и
почему важно», ссылка на первоисточник, код оценки (`references/sources.md`, «Шкала»), откуда
узнали; в конце — «стоит полного поиска» и ленты-кандидаты на отключение.

## 3. `watch`

### 3.1. Команда

```
deep_search.py watch [--library ПУТЬ] [--only ГРУППА|ID] [--since ДАТА] [--dry-run] [--json]
```

- `--only` — одна группа или лента; `--since` — окно вместо расчётного; `--dry-run` — без записи
  `new/` и `state.json`; `--json` — найденное в stdout строками JSON вместо таблицы.
- Код выхода: 0 — запуск прошёл, даже если часть лент не ответила; 2 — ошибка вызова (нет
  библиотеки, битый `feeds.json`).

### 3.2. Типы лент

| Тип | Что | Ловушки, которые разборщик обходит |
|---|---|---|
| `rss` | RSS 2.0 и Atom | ответ 200 с HTML — не лента (проверка корневого тега); gzip без запроса; `lastBuildDate` канала не дата записи [01] |
| `sitemap` | карта сайта с `lastmod`, отбор по `match.path` | `lastmod` — дата правки (`date_kind: modified`); индекс карт — один уровень вложенности [01] |
| `github_releases` | выпуски через API (`params.repo`) | `releases.atom` держит только 10 записей — берётся API; токен из `GITHUB_TOKEN`; без токена 60 запросов в час [01] |
| `hf_trending` | модели Hugging Face в тренде, созданные за окно | `sort=createdAt` — шум; только `trendingScore` [02] |
| `hf_papers` | статьи недели (`?week=ГГГГ-Wнн`) с голосами, порог `params.min_upvotes` | `sort=trending` отдаёт старые статьи [02] |
| `openrouter` | каталог моделей, новые по `created` | `created` — появление в каталоге; варианты `:free`, `:batch` склеиваются по `canonical_slug` [02] |
| `hn` | Hacker News через Algolia, `params.query` списком, порог `params.min_points` | `numericFilters` URL-кодировать, иначе 400; запрос ищет не только по заголовку — фильтр интересов [02] |
| `telegram` | `t.me/s/<канал>`, листать `?before=` до прошлого опроса, не больше 4 страниц | вложенные `div` в тексте — разбор с глубиной; редирект на `t.me/<канал>` — нет превью; посты без текста пропускаются [02] |
| `page` | снимок текста страницы без ленты; новое — добавленные строки | дата — время опроса; меню и подвал отсекаются `match` [01] |

Новый тип — только кодом с тестом; новая лента существующего типа — строкой в наборе.

### 3.3. Шаги

1. Собрать набор (2.2–2.3), отбросить отключённые.
2. Окно: у ленты с `last_ok` — с `last_ok` минус сутки (перекрытие ловит `seen`); первый запуск —
   7 дней; `--since` — как задано.
3. Опросить параллельно, не больше 8 одновременно; к одному хосту — последовательно с
   `min_interval`; таймаут 20 с; тело до 4 МБ; User-Agent описательный или `browser` по `ua`.
4. Разобрать по типу; дата из записи; дата в будущем больше чем на сутки или без года — как нет
   даты; запись старше окна — отбросить.
5. Ключ записи — ссылка, приведённая как `source_key` (регистр схемы и хоста, без `utm_*` и
   фрагмента); нет ссылки — id записи ленты. Ключ в `seen` — отбросить.
6. Склеить дубли между лентами: один ключ; либо внешняя ссылка из поста канала, HN или рассылки
   совпала с ключом другой записи; либо совпали заголовки после нормализации (регистр, пробелы,
   знаки). Запись склейки берёт ссылку и дату самой ранней записи первоисточника (`labs`, `releases`),
   иначе самой ранней вообще; `feeds` — все ленты, `first_feed` — давшая раньше всех.
7. Фильтр: `filter: always` проходит; `interests` — только с совпадением слов в заголовке или
   выдержке; совпавшие группы — в `interests` записи.
8. Записать `new/<дата>.jsonl`, обновить `state.json` (счётчики 2.4, `fails`, `last_error`).
9. Вывести сводку (3.4).

### 3.4. Вывод

```
watch: 2026-10-09 — новых 37 (labs 9, releases 6, aggregators 12, newsletters 4, telegram 6); лент 41, не ответили 2
2026-10-07  labs        Claude Haiku 5.5                          https://…  ×3  models
2026-10-08  aggregators StepFun Step-5 preview (OpenRouter)        https://…      models
…
не ответили: x-ai-news (403 ×3 подряд — проверить или отключить), qwen-blog (HTML вместо ленты)
на пробу без своего за 8 запусков: <id>, <id> — предложить отключить
найденное: <библиотека>/watch/new/2026-10-09.jsonl
```

Порядок: `labs` и `releases`, затем по числу лент (`×N`), затем по дате. Предел — 9 000 символов
(основная спецификация, 7.2), хвост «… ещё N»; полный список — в файле.

### 3.5. Ошибки

Лента, которая не ответила, прислала не тот формат или не разобралась, не ломает запуск: строка в
«не ответили», `fails + 1`, `last_error` — короткая причина без адресов с учётными данными. После 3
провалов подряд — пометка «проверить или отключить». Лента «на пробу» после 8 запусков с
`unique = 0` — пометка «предложить отключить». Битый `state.json` — переименовать в
`state.json.bad-<дата>` и начать с первого запуска, сказав об этом.

### 3.6. Безопасность

Содержимое лент — данные, не инструкции: в `new/` попадают только заголовок, ссылка, дата и выдержка
до 300 символов без управляющих символов. Токен GitHub — только в заголовке запроса к
`api.github.com`, в вывод и файлы не попадает.

## 4. Сценарий «что нового»

Новый подфайл `references/watch.md` (маршрут из ядра «Что нового, мониторинг»), шаблон
`templates/digest.md`.

1. Нет `new/<сегодня>.jsonl` — запустить `deep_search.py watch`.
2. Прочитать найденное (`jq`, по группам), не открывая страниц.
3. Отобрать важное по интересам: новинка меняет выбор (модель, инструмент, цена, лимит, условия),
   а не просто вышла. Признаки важности — первоисточник `labs`, `×N` лент, рейтинг HN, голоса за
   статью.
4. По каждому отобранному — открыть первоисточник (текст — `references/environment.md`), 1–2
   строки «что это и почему важно», код оценки; новость только из `telegram` или `aggregators` без
   первоисточника — с пометкой, буква не выше D.
5. Записать дайджест по шаблону; в конце — «стоит полного поиска» с готовой формулировкой вопроса
   и типом (`comparison` для моделей и т. п.) и ленты-кандидаты на отключение из вывода `watch`.
6. Человек просит полный поиск — обычный прогон с брифом и `preset: ai`.

Уровень — S/M без дерева; субагент — только если отобранного больше 15.

## 5. `facts`

### 5.1. Команда

```
deep_search.py facts <цель> [--json]
```

Цель: ссылка на репозиторий (GitHub, GitLab, Codeberg и любой Forgejo/Gitea, Gitee); `OWNER/REPO`
(GitHub); purl пакета (`pkg:pypi/requests`, `pkg:npm/react@18.3.1`). Не распозналась — ошибка вызова
с примерами.

### 5.2. Источники

| Поле | Откуда | Когда |
|---|---|---|
| лицензия, архивирован, последний коммит, звёзды, последний выпуск | API хостинга | цель — репозиторий |
| версии, лицензии версий, уязвимости (ключи advisory) | deps.dev; OSV для версии | цель — пакет; у репозитория — пакет, если deps.dev знает связь |
| конец поддержки версий | endoflife.date по имени продукта | 404 — поле пустое, не ошибка |
| загрузки, зависимые | ecosyste.ms | есть пакет |
| оценка сопровождения | Scorecard | репозиторий на GitHub |
| в дистрибутивах | Repology по имени | всегда; имя может не совпасть — так и сказать |

Опрос параллельный, таймаут 15 с, токен GitHub — из `GITHUB_TOKEN`.

### 5.3. Вывод

Строка на значение: `поле | значение | источник §путь | дата`. Источник — адрес запроса, путь — к
полю JSON: ветка пишет это уликой уровня A без пересказа. Предел — 2 000 символов; не ответившие
источники — отдельной строкой. `--json` — то же объектом. Код выхода 0, ошибка вызова — 2.

## 6. Пресет `ai` и набор лент

### 6.1. `presets/ai.md`

Обязательные разделы пресета (`self`) плюс свои; до 12 000 символов.

- **Типы вопроса:** сравнить модели — `comparison`; чем заменить модель, стоит ли переходить —
  `replacement`; выбрать инструмент для агента или программу для ИИ — `options`; правда ли, что
  поставщик изменил X, — `validation`; «что нового» — сценарий 4.
- **Первоисточники по шкале:** A — карточка и системная карточка модели, документация, страница цен,
  журнал изменений, список моделей в API поставщика, статья о модели (о фактах о себе); B —
  воспроизводимые независимые оценки с открытой методикой (Epoch AI, официальные таблицы
  бенчмарков); C — LMArena (голоса людей, методика оспаривается), отчёты об использовании; D —
  OpenRouter, рассылки, Telegram; E — бенчмарки вендора, маркетинг, утечки.
- **Источники охвата:** OpenRouter, Hugging Face, данные LMArena, каталоги Epoch AI, рассылки,
  `watch` и прежние дайджесты библиотеки.
- **Шаблоны запросов:** выход модели, сравнение, цены и лимиты, отключение модели, опыт
  использования, альтернативы программе — по-английски и по-русски.
- **Ловушки:** выборочные бенчмарки вендора; загрязнение тестов обучающими данными; дата OpenRouter —
  не дата выхода; preview и общая доступность; снимки моделей с датой в имени; цены по длине
  контекста и режиму (batch, кэш); доступность по регионам.
- **Данные для сравнения:** контекст, цены, модальности, лицензия весов, где доступна (API, веса,
  регион), независимые оценки, дата выхода, дата среза знаний.
- **Свежесть:** цены, лимиты, доступность — V3; возможности — V2; архитектура и статьи — V1.

### 6.2. `presets/ai-feeds.json`

Только ленты, проверенные `curl` [01, 02]: первоисточники лабораторий с машинным каналом (11 своих
лент и карт сайта, Яндекс и Сбер — блоги на Хабре), организации Hugging Face и выпуски GitHub для

## 7. Схемы в руководстве

В `docs/guide.md` — схемы на Mermaid (на GitHub — рисунок, иначе читается как текст):

1. **Как устроен поиск:** вопрос → этап 0 (что уже знаем) → бриф → дерево веток → у ветки лестница
   источников своей области (специализированный API или `facts` → веб-поиск → текст страницы →
   архив) → проверка → сведение → хранилище.
2. **Как `watch` читает сайт:** есть RSS или Atom → `rss`; нет — карта сайта с датами → `sitemap`;
   нет — выпуски GitHub или организация Hugging Face → `github_releases`, `hf_*`; нет — снимок
   страницы `page`; закрыто (Cloudflare, капча) — только через агрегаторы.
3. **Области и чем они закрыты** — ссылка на карту покрытия (5.5) и строка о мониторинге.

## 10. Тесты

`python3 -m unittest discover tests`, сеть не трогается: функция запроса передаётся внутрь, как
`fetcher` в `doctor`; образцы ответов — маленькие файлы в `tests/fixtures/watch/` по одному на тип и
на ловушку (HTML вместо ленты, gzip, вложенные `div`, будущая дата, `lastmod`).

- каждый тип ленты разбирается в записи с датой и ключом;
- второй запуск с тем же ответом не даёт нового; `seen` ограничен 500;
- склейка: одна ссылка в блоге, HN и канале — одна запись `×3`, `first_feed` верный, счётчики
  `first` и `unique` верные;
- окно первого запуска — 7 дней; `--since` и `--dry-run` работают;
- упавшая лента не ломает запуск, третий провал подряд даёт пометку; битый `state.json` переименован;
- `feeds.json` библиотеки: `disable`, `add`, `override`, неизвестный тип — ошибка вызова;
- вывод не длиннее предела, хвост «… ещё N»; токен не попадает в вывод и файлы;
- `facts`: разбор цели всех видов; сборка полей из подменённых ответов; 404 endoflife — пустое поле;
- `self` на наборе лент: битый JSON, повтор id, неизвестный тип — нарушения;
- `init` создаёт `watch/`; `lint --store` ловит битый `state.json`.
