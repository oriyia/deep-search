Когда читать: этап 0 — что уже знаем; этап 6 — сохранение; тема устарела (`mode: update`).

# Хранилище

Содержание: Где · Раскладка · Прогон · Форматы · Переиспользование · Запись · Против свалки.
Скрипт — `python3 <папка скилла>/deep_search.py`, ниже — `deep_search.py`.

## Где

- **Библиотека** — отдельный git-репозиторий, общий для проектов; путь — в `DEEP_SEARCH_LIBRARY`;
  Claude Code нужен доступ через `additionalDirectories`.
- **Проект** — `research/` в корне проекта. Конфиденциальное — только сюда.
- Поле брифа `store` выбирает, куда пишет прогон; этап 0 смотрит в оба. Нет `INDEX.md` —
  хранилища нет: сказать и предложить `deep_search.py init <путь>`.
- `store: none` — только на S: на диск не пишется ничего, этап 6 пропускается.

## Раскладка

```text
<хранилище>/
  INDEX.md             строка на тему; собирает `index`; ≤100 строк
  log.md               события; только дописывается
  topics/<slug>.md     карточка темы — синтез; ≤300 строк
  claims/<slug>.md     утверждения темы; ≤200 строк
  sources.md           источники, строка на источник
  runs/<дата>-<slug>/  прогоны, неизменяемые, вне INDEX
  raw/                 копии критичных страниц; .gitignore
  archive/             архив тем; скрыт через .ignore
```

`<slug>` общий у прогона, карточки и утверждений: `grep -r <slug>` собирает тему.
Два слоя: свидетельства (прогоны, источники, утверждения) молча не правятся; синтез (карточки,
INDEX) переписывается и источником не служит — утверждения ссылаются только на внешние `S-…`.
`raw/<sha256 содержимого>.<расширение>` — копия для себя; хеш и архивный URL — в `capture`
журнала ветки.

## Прогон

Папка — `runs/<ГГГГ-ММ-ДД>-<slug>/` (при совпадении `-2`), имя — `id` брифа. Создаётся на этапе 1,
после этапа 6 не меняется: повторный поиск — новая папка.

- Ведущий: `brief.md`, `plan.md`, `manifest.json`, `report.md`, `branches/<task_id>.task.yaml` —
  задание ветке.
- Ветка: `branches/<task_id>.return.yaml` — ответ; `.md` — улики; `.jsonl` — журнал.
- Проверяющий: `verify.md` — протокол проверки.

`plan.md` и статусы веток — `references/branching.md`, «plan.md прогона»; журнал и улики —
`references/sources.md`, «Журнал и улики»; отчёт — `references/verify-merge.md`, «Отчёт».

`manifest.json` заводится с папкой, `env` — вывод `deep_search.py doctor --json`; остальное —
по ходу, сверить перед этапом 6. Бюджет и остановка — `references/branching.md`.

```json
{"id": "2026-10-05-<slug>", "tier": "M", "preset": "technology", "env": {},
 "budget": {"planned": 0, "used": 0}, "stop_reason": "",
 "counts": {"found": 0, "dupes": 0, "screened": 0, "kept": 0},
 "branches": [{"id": "B1", "status": "done"}]}
```

## Форматы

Реестр — только таблица Markdown: шапка, разделитель, строка на запись с `| <id>`; `|` в тексте —
`\|`.

**Утверждение** — `claims/<slug>.md`:

`| id | код | утверждение | предмет | источники | цитата | проверено | свежесть | статус |`

- `id` — `C-<slug>-<NNN>`, три цифры, по порядку в теме; номер не переиспользуется.
- `код` — код оценки `^[A-F][1-6]!?$`: `references/sources.md`, раздел «Шкала».
- `предмет` — `entity_key` объекта, один во всех темах обоих хранилищ; `источники` — `S-…[ §место]` через `; `, только внешние.
- `цитата` — дословно, ≤25 слов, в «»; без цитаты не записывается. `проверено` — дата сверки.
- `свежесть` — `V2→ГГГГ-ММ-ДД`, класс и срок: `references/sources.md`, раздел «Свежесть»; V0 —
  просто `V0`.
- `статус` — `live` · `stale` · `superseded→C-…` · `retracted`.

`| C-<slug>-014 | B2 | <утверждение> | <entity_key> | S-3f2a91c0 §2; S-7b1c04aa | «цитата» | 2026-10-05 | V2→2027-01-03 | live |`

**Источник** — `sources.md`:

`| id | тип | заголовок | владелец | опубликовано | обращение | URL | архив | надёжен для |`

- `id` — `S-` + первые 8 hex sha256 ключа. Ключ — первый доступный: DOI в нижнем регистре →
  канонический URL без фрагмента и `utm_*` → sha256 текста.
- `тип` — `docs`, `paper`, `repo`, `forum`, `vendor`…; `URL` — или DOI; `архив` — архивный URL
  или файл `raw/`, иначе `—`.

**INDEX** — собирает `index` из frontmatter карточек, руками не правится:

`| slug | TL;DR | keywords | статус | проверено | годен до |`

Столбцы — из полей `tldr`, `aliases` и `keywords`, `status`, `checked`, `expires`.

**log.md** — заголовок и до двух строк текста; новое — в конец:

`## [ГГГГ-ММ-ДД] <вид> | <slug> | <прогон>`

Виды — «Запись», шаг 5; без прогона — `—`.

**Карточка** `topics/<slug>.md` — по `templates/topic.md`. Frontmatter — плоские скаляры, списки
через `, `: `topic` (slug), `title`, `tldr` (≤100 символов), `aliases` (RU и EN), `keywords` (RU и
EN, по основам), `status` (`live` · `stale` · `archived`), `checked` (дата последней сверки),
`expires` (минимум дат свежести живых утверждений; все V0 — `—`), `runs` (id прогонов).

## Переиспользование

На старте сессии ничего не грузится. Этап 0 — не больше трёх файлов:

1. grep по `INDEX.md` обоих хранилищ — ключевые слова на русском и английском, по основам:
   `grep -i -E 'основ|stem' "$DEEP_SEARCH_LIBRARY/INDEX.md" research/INDEX.md`. Тема в обоих —
   сверить выводы и `checked`; расхождение — в `prior_work`.
2. До двух карточек: frontmatter, «Ответ на …» и «Отклонено» — строки по `grep -n '^## '`.
3. grep по `claims/<slug>.md` — строки по `C-…` из карточки или по словам.
4. Источник по id — если нужно: `grep '^| S-3f2a91c0' sources.md`.

Нужно больше трёх файлов — чинить `keywords` и `aliases` карточки, а не читать дальше.

Что найдено — в бриф: `prior_work` (что искали и решили), `exclusions` (из «Отклонено», если не
сработало «Пересмотреть, если»), `since` в `limits` (дата `checked`), `store_topic` (slug темы).
Просроченное утверждение — «6», гипотеза для перепроверки, а не факт.

- Темы нет — `mode: one_off`, новый slug.
- Тема живая и отвечает — ответ из хранилища со ссылками на `C-…`; искать, если человек просит.
- Устарела или неполна — `mode: update`: только новое после `checked`, перепроверка просроченного,
  отклонённое заново не исследуется.

## Запись

Пишет один автор — ведущий или субагент сохранения со сведённым итогом:

1. **Источники** — только те, на которые ссылаются утверждения; тот же ключ заменяет прежнюю
   строку.
2. **Утверждения.** Только сведённые и с цитатой — новые строки с номерами после последнего.
   Прежнее, которое новое заменяет, — `superseded→C-…`; опровергнутое — `retracted`; просроченное и
   не перепроверенное — `stale`. Перепроверка подтвердила без изменений — у строки меняются только
   `проверено`, `свежесть`, `статус` (запись в `log.md`); изменились смысл, цитата, источник —
   новая строка.
3. **Карточка** — из `templates/topic.md` или прежняя; разделы переписываются. Вывод — со ссылкой
   на живое `C-…`, иначе — в «Открытые вопросы». `checked` — только при сверке с источником;
   `expires` пересчитать; в `runs` — id прогона; нет живых непросроченных — `status: stale`.
4. `deep_search.py index <хранилище>`, затем `lint --store <хранилище> --run <прогон>` и
   `--also <второе хранилище>`, если оно есть. Нарушения исправить. `claim-subject*`,
   `topic-twin` — прежнее о предмете, обновлённом прогоном: заменить, перепроверить, `stale` или
   оставить; неснятое расхождение — в «Открытые вопросы» обеих тем. Прочее — в отчёт, туда же.
5. **Строка в `log.md`:** `search` — новый прогон, `update` — прогон `mode: update`, `verify` —
   перепроверка без прогона, `archive` — тема ушла в архив.

Черновики, сниппеты, расшифровки остаются в прогоне. Задан `report_path` — туда копия
`report.md`. Скилл не коммитит: хранилище коммитит пользователь.

## Против свалки

- Единица — тема, а не прогон.
- Сверх бюджета из «Раскладки»: INDEX — делить по областям, с пользователем; карточка — сжать
  синтез; утверждения — делить на подтемы со своими slug.
- Отклонённое не удаляется: причина и «Пересмотреть, если».
- Архив: `status: archived`, карточка и реестр утверждений — в `archive/topics/` и
  `archive/claims/`, `index` убирает строку из INDEX, запись `archive` в `log.md`. Источники
  остаются в `sources.md`.
