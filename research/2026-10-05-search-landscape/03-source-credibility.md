# 03. Оценка источников и подтверждённости утверждений

2026-10-05. [n] — источник в конце; [?] — не проверено по первоисточнику; «препринт» — без рецензии; «заявл. вендора» — о себе.

## Коротко

- Базовая пятиуровневая шкала скилла ранжирует типы источников. Для универсального поиска нужны две оси по образцу FM 2-22.3 [2]: надёжность источника A–F × подтверждённость утверждения 1–6, код `B2`. Оценивается пара «источник × утверждение».
- Буква ставится по 4 вопросам: подотчётность → заинтересованность → доступ к факту → метод. Цифра — по правилам-потолкам из набора улик: «на глаз» оси сливаются [3][4].
- Подтверждение считается по независимым происхождениям, а не по упоминаниям. Синдикация и пересказы пресс-релиза — один источник [10][11][17]; LLM принимают повтор за подтверждение [38].
- Свежесть — две даты и класс изменчивости со сроком перепроверки; просроченное получает «6».
- Главный риск агента — ссылка не подтверждает утверждение. Рабочие и релевантные ссылки фактически верны в 39–77 % случаев [40]; у 31 % ответов ИИ-ассистентов о новостях — проблемы с источниками [30].
- Уровни 1–5 базовой шкалы переходят в A–E. Добавляются F, правило «вендор: A — факты о себе, E — оценки себя» и потолки: только D — не выше 3, только E — не выше 4.

## 2. Шкала

### 2.1. Принципы

1. Оценивается пара «источник × утверждение» [10][12]. Документация вендора — A для «опция X есть в версии Y», но E для «самая быстрая СУБД».
2. Буква — по свойствам источника, цифра — по уликам и правилам [3][4].
3. Вывод агента цифру не получает: он помечается «вывод» и ссылается на утверждения [6][10].
4. Слабо подтверждённое хранится атрибутированно: «по заявлению вендора, …» — атрибуция A1, содержание E4.

### 2.2. Ось 1 — надёжность источника для утверждения

Вопросы проверяются сверху вниз; букву даёт первый подошедший.

| | Критерий | Примеры |
|---|---|---|
| F | Неясно, кто стоит за источником; боковое чтение ничего не дало | Страница без владельца |
| E | Заинтересован в утверждении (оценка себя, сравнение с конкурентами, о третьих лицах) или неподотчётен | Маркетинг, пресс-релизы, партнёрское, фермы контента, соцсети, выводы ИИ |
| A | Происхождение или официальная запись факта; подлинный; версия и дата совпадают | Код, документация версии, LICENSE; официальное опубликование; реестр; датасет; статья — для своих результатов |
| B | Независим, наблюдал сам, метод воспроизводим или проверен | Бенчмарк с данными; рецензируемое исследование; официальная статистика; оригинальный репортаж; справочно-правовая система — для текста нормы |
| C | Свидетельство из первых рук без метода; автор установим | Отчёт об эксплуатации, постмортем, доклад; препринт без данных |
| D | Пересказ, сводка, мнение без доступа к факту | Radar, энциклопедии, каталоги, новости-пересказы, форумы |

Буква определяется по происхождению, а не по сайту. Материал вендора на чужом сайте остаётся E; чужой контент на авторитетном домене его букву не наследует (site reputation abuse [12]).

Понижение на ступень даёт каждый признак: косвенность (другая версия или среда, indirectness [8]) или красный флаг (раздел 5). Отозванное не используется. Реестр источников (п. 12 «Что взять») сдвигает букву на ступень (USEBYOTHERS [10]).

### 2.3. Ось 2 — подтверждённость утверждения

| | | Условие |
|---|---|---|
| 1 | Подтверждено | (а) «Документ, код или реестр говорит X» проверено по открытому A нужной версии; или (б) ≥ 2 независимых A/B согласуются, и ни один A/B не противоречит. Для эмпирики — обзор с уверенностью High |
| 2 | Вероятно | Один A/B или ≥ 2 независимых C; противоречий нет |
| 3 | Возможно | Один C; любое число D; неснятое противоречие сопоставимых (метка `!`) |
| 4 | Сомнительно | Только E, или всё восходит к одному E |
| 5 | Опровергнуто | Противоречит A или ≥ 2 независимым B |
| 6 | Нельзя судить | Страница не открыта (сниппет, пейвол), источник не найден или истёк срок класса |

Потолки: только E — не выше 4; только D — не выше 3; один C — 3; один B — 2.

Условие (а) — для «в документации версии 18 описано X»; для «X так работает на практике» нужно (б). Исключительное утверждение или тема с высокими ставками (YMYL [12]) получает «1» только по (б) [10].

### 2.4. Компактная запись

Код — `<буква><цифра>[!]`, буква по лучшему поддерживающему источнику: `A1`, `B2`, `C3!`, `E4`.

Улика в журнале, ≈ 30–50 токенов:
`ev7 | 2026-10-05 | B | consultant.ru/…/ст.4 | orig: 5-ФЗ офиц. опубл. | → c3 | «Официальным опубликованием … считается первая публикация его полного текста…»`

Утверждение в хранилище, ≈ 40–80 токенов:
`c3 | B2 | 2026-10-05 | V1→2027-10 | ev7 | Офиц. опубликование ФЗ — первая публикация полного текста в «Парламентской газете», «Российской газете», СЗ РФ или на pravo.gov.ru (5-ФЗ ст. 4); для A1 сверить с pravo.gov.ru`

Примеры:
- `A1` — Redis 8 доступен и под AGPLv3 [47].
- `E4` — «up to 87% faster commands» у Redis 8 [47]: хранится как «по заявлению Redis».
- `B2` — ст. 4 5-ФЗ по КонсультантПлюс [45].
- `A1` — «authentic» только электронное OJ (ст. 1 Регламента 216/2013) [46].

## 3. Независимость и правила подтверждения

Независимый источник не имеет «vested interest» в предмете и обладает редакционной независимостью [10, WP:IS]. Два источника независимы, если ни один не взят из другого и у них нет общего происхождения.

Признаки общего происхождения: совпадающие формулировки и цифры; ссылки на один материал; синдикация («treated as the same single source» [10]); пересказ пресс-релиза; общий владелец; Википедия как источник для СМИ (citogenesis [11]); один вендорский бенчмарк в нескольких обзорах. Пример цены ошибки: если совет в пресс-релизе преувеличен, его преувеличивают и 58 % новостей, иначе — 17 % [17].

Ветвление: у улики поле `orig` — самое раннее найденное происхождение. Ветка независимости не видит, поэтому цифру ставит сводящий агент по уникальным `orig`.

| Тип утверждения | Что нужно для «1» | Иначе не выше |
|---|---|---|
| Содержание документа, кода, нормы; цитата | Открытый A, версия, дата, дословно | 2 — по B |
| Факт о себе: лицензия, выпуск | A владельца; ABOUTSELF: не самовосхваление, не о третьих лицах [10] | 2 |
| Состояние: выпуск, сопровождающие, цена | A и дата в сроке класса | 6 после срока |
| Эмпирика: производительность, эффективность | ≥ 2 независимых воспроизводимых B или обзор High | 2 — один B; 3 — C; 4 — вендор |
| Оценка («лучший», «популярный») | Независимые B/C с явными критериями | Мнение с атрибуцией |
| Отрицание («не поддерживает») | A прямо пишет «не поддерживается» | 2: «не найдено в [источники, дата]» |
| Событие, новость | Документ или ≥ 2 независимых оригинальных репортажа | 2 |
| Число, статистика | Исходные данные | 3 |
| Исключительное, высокие ставки | ≥ 2 независимых A/B [10] | 3 |

## 4. Свежесть

- **Две даты в ISO 8601:** публикации или изменения источника и проверки утверждения; у версионных фактов — «на версии X». Для выпусков, лицензий, активности и сроков поддержки дата получения обязательна.
- **Классы изменчивости** (проект; сроки эвристические):
  - V0 — неизменное: история, спецификация по постоянной ссылке. Перепроверять только при исправлениях и ретракциях.
  - V1 — медленное: нормы, архитектура, консенсус. Срок 12 мес.; медицинские обзоры старше ~5 лет часто уже заменены [10].
  - V2 — среднее: лицензия, сопровождающие, поддержка, тарифы. Срок 90 дней. Redis перешёл на SSPL в 03.2024 и добавил AGPLv3 в 05.2025 [47].
  - V3 — быстрое: последний выпуск, цены, события, рейтинги, звёзды. Срок 7–30 дней и перед любым решением.
- **Пробелы авторитетных баз.** С 15.04.2026 NIST обогащает CVE в NVD по приоритетам, остальные — «not scheduled for immediate enrichment» [48]. «Нет в NVD» ≠ «нет уязвимости».
- **Ссылки умирают.** 38 % страниц 2013 г. недоступны; в 54 % статей Википедии есть мёртвая ссылка [18]. Хранить постоянную ссылку и архив; мёртвый URL проверять в Wayback — устарел он или выдуман [19].
- **Новее ≠ надёжнее.** LLM-ранжировщики продвигают тексты с подставленными свежими датами: средний год топ-10 сдвигается до 4,78 года [36].
- **При повторном использовании** просроченное получает «6» и служит гипотезой до перепроверки.

## 6. ИИ-агенты: перекосы и противодействие

Качество ссылок:
- Генеративные поисковики (2023): ссылками подтверждены 51,5 % предложений; своё предложение подтверждают 74,5 % ссылок [28].
- CJR / Tow (8 инструментов, 1 600 запросов): неверно > 60 % (Perplexity 37 %, Grok 3 94 %); ссылки на синдицированные копии вместо оригинала [29].
- EBU/BBC (22 организации, > 3 000 ответов): у 45 % ответов существенная проблема, у 31 % — с источниками (сведений нет в источнике, источника нет, атрибуция неверна); «ceremonial citations» [30].
- Агенты глубокого исследования (2026, препринты): ссылки рабочие > 94 %, но верны 39–77 %; с ростом вызовов от 2 до 150 точность падает ≈ на 42 % [40]. 30,6 % ссылок искажают источник [41]; 3–13 % URL выдуманы [19].

Перекосы отбора:
- повтор пересиливает надёжность [38];
- предпочтения источников не снимаются промптом [39];
- ретриверы ставят LLM-тексты выше [33];
- ИИ-поиск тяготеет к брендам и earned media [32];
- GEO поднимает видимость до 40 % [31];
- модели перенимают неверный контекст вопреки верному знанию > 60 % случаев [34];
- ИИ-судьи поддаются поддельным ссылкам [37];
- оценки СМИ моделями согласуются с экспертами умеренно (ρ ≈ 0,50) [35];
- текст страницы ухудшает суждение модели об авторитетности [42].

Противодействие — пп. 4, 7, 10, 14 «Что взять» и поиск первоисточника напрямую (сайт проекта, реестр, портал).

## 8. Пятиуровневая шкала типов источников на двух осях

Базовая шкала типов источников скилла: первоисточники → воспроизводимые бенчмарки и публикации с кодом → отчёты об опыте эксплуатации → обзоры экспертных сообществ → материалы вендора (и выводы ИИ).

| Уровень | Буква | Уточнение |
|---|---|---|
| 1. Первоисточники | A | В пределах полномочий: трекер — A для «сопровождающие признали ошибку», C для симптомов со слов пользователей |
| 2. Воспроизводимые бенчмарки, открытый код | B | Чек-лист [23]; препринт — с меткой |
| 3. Опыт эксплуатации, разборы неудач | C | Два независимых → 2 |
| 4. Обзоры экспертных сообществ | D | «Фильтр внимания» = потолок 3 |
| 5. Вендор; выводы ИИ | E | «Перечень заявлений» = потолок 4; факты о себе — A |
| — | F | Новое: происхождение не установлено |

Базовые правила работы с источниками переходят в правила цифры: «2 и более независимых источника» → условие (б); «сведения только от вендора» → потолок 4; «вывод только по открытой странице» → сниппет = 6.
